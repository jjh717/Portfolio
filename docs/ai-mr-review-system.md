# AI MR 리뷰 시스템 — 구성과 운영

GitLab MR을 자동 감지해 AI 리뷰를 만들고, **사람이 확인한 것만** GitLab에 등록하는 — 그리고 **쓸수록 리뷰어를 닮아가는** 개인용 시스템. 맥에서 상시 돌고 API 요금은 없다.

> 구성·운영 문서 · 2026-09-26 기준 실측 (큐 보호 불변식 공유 · 자동 심화 OFF · 결과 알림 3종 · 재현 하네스 하드닝 반영)

|:---:|:---:|:---:|:---:|
| 상시 프로세스 + 일회성 세션 4종 | 보존 중인 리뷰 (30일) | 그 안의 지적 이슈 | 추가 API 비용 |

## 01. 핵심 원칙

- **리뷰가 리뷰어를 닮아간다 — 이 시스템의 핵심.** 등록·건너뜀·질문이 전부 학습 신호가 되어, 같은 MR이라도 쓰는 사람마다 지적의 깊이·감도·문장이 달라진다. 목표는 동일한 리뷰가 아니라 **각자에게 맞는 리뷰** — 공용 기준(13관점)이 바닥선을 지키고, 모든 지적에 근거(verify)가 붙어 취향과 사실을 분리한다.
- **자동 등록은 없다.** GitLab에 나가는 것(승인 110건·코멘트 70건)은 전부 사람이 버튼을 누른 것. 자동으로 도는 건 **탐색까지**다.
- **AI 구간과 비-AI 구간을 분리.** 감지·알림·서버는 순수 파이썬이라 AI가 죽어도 멈추지 않는다.
- **상태 전이는 한 함수로.** 큐 보호 불변식(`apply_status`)을 `set_status`와 개별 코멘트 등록이 **공유**한다. 락 안에서 status를 직접 대입하던 경로 하나가 3주간 이 보호를 우회해, 재리뷰를 기다리던 MR이 개별 코멘트 한 번에 큐에서 빠져 **4일 미리뷰**된 사고에서(2026-09-23). 남은 직접 대입은 함수별 개수로 정적 가드 테스트에 고정했다.
- **본인 MR은 리뷰 안 함 — 두 갈래.** 내 명의로 직접 올린 MR은 생성 시점에 `own`(2026-09-23, 자동화 계정 명의만 보던 필터를 첫 직접 명의 MR이 통과한 사고에서). 자동화 계정 명의 MR은 커밋 이메일 과반으로 판별하되 **분모는 사람 커밋만** — 릴리스 자동화 커밋이 섞여 뚫린 사고(09-09)에서. 애매하면 숨기지 않고 노출.
- **Draft도 리뷰 안 함.** 해제되는 순간 자동으로 대기열에 들어간다.

## 02. 프로세스

| 구성요소 | AI | 실행 | 역할 |
|---|:---:|---|---|
| **워처** | 안 씀 | `mr_watch.py` · 3분마다 | 새 MR·새 커밋·base 이동·Draft 해제 감지 → 대기열 + 맥 알림. 본인 MR 판별과 30일 히스토리 청소, 결과 알림 3종도 담당. |
| **리뷰 세션** | AI | tmux · `review-N` · MR마다 일회성 (2026-08-26 stateless) | MR 1건 = 세션 1개. 서버가 대기열에서 **동시 2건**까지 스폰하면, 세션은 그 MR만 리뷰하고 스스로 종료한다. 감지 후 보통 3분 안에 시작. |
| **질문 루프** | AI | tmux · `mrchat` · 이벤트 구동 | 리뷰에 질문을 남기면 깨어나 답한다. 추측 금지 — GitLab 소스를 직접 열어 확인. 런처가 기동 다이얼로그(트러스트·effort 넛지)를 대신 처리한다. |
| **대시보드 서버** | 안 씀 | `127.0.0.1:8765` · 상시 | 리뷰 표시 + 등록 버튼 처리 + **리뷰·재검토·심화·재현 세션 스폰**. 로컬 전용, 죽으면 즉시 재기동. |

> **일회성 세션은 넷.** 리뷰(review-N)·🔁 2차 의견(이슈 1건 반증)·🔬 심화 라운드(모델 2개 병렬 탐색)·**🧪 런타임 재현(실제로 빌드해서 돌려보기)** 전부 필요할 때 떠서 일을 마치고 스스로 종료한다. 심화는 **2026-09-18부터 자동 발화 OFF**(`MR_DEEP_AUTO=1`로만 ON) — 남은 건 수동 🔬와 잘린 심화의 재개다. 재현은 사람이 켠다. 상시로 남는 건 워처·서버·질문 루프 셋뿐.

> **왜 리뷰를 상주에서 일회성으로 바꿨나(2026-08-26).** 장수 세션은 컨텍스트 압축이 리뷰 기준의 원문을 요약으로 바꿔치기해 **기준을 안 읽은 리뷰가 18건** 나왔다. 매번 새 세션이 기준을 새로 읽으면 이 문제와, 그걸 막으려던 장치들(24시간 수명 캡·침묵 블록 감지·큐 몰림 가속)이 통째로 사라진다. 비용은 리뷰당 기준 로드가 늘지만 1차 리뷰가 전체 사용량의 9%라 소폭.

> **복구는 세션 실존으로 판정.** "리뷰 중"인데 그 세션이 죽어 있으면 워처가 **즉시** 대기열로 되돌린다(3회 연속 실패 시 자동 중단 + 맥 알림, ▶가 리셋). 멈춤·크레딧 창 블록은 스폰 워치독이 흡수 — 2분 안에 크레딧 게이트면 다른 모델로 재스폰, 상한을 넘으면 원인 불문 강제 종료 후 재큐. 워처 자체의 생존은 `.poll-heartbeat`로 대시보드 엔진 배지에 표시된다.

> **무인 세션의 실패는 침묵이라, 원인이 아니라 결과로 회수한다(2026-09).**
> ① **API 오류 뒤 idle** — `API Error: 5xx`로 턴이 끝나면 세션은 죽지도 일하지도 않는다(실제로 15분 묶였다).
> ② **정체** — 세션 트랜스크립트가 10분간 안 자라면 회수(정상 세션의 최대 공백은 실측 3분).
> ③ **벽시계 상한** — 워치독의 `sleep`은 맥이 잠들면 같이 멈추므로, 자원 자체의 나이를 재는 백스톱을 따로 둔다.
> 셋 다 **무장 시점의 세션 나이가 같을 때만** 회수한다 — 같은 이름으로 다시 뜬 후속 세션을 옛 감시자가 죽이던 사고를 막는 세대 가드다.

> **세션 종료는 한 경로로(2026-09-16).** `kill_session`이 ppid 사슬로 자손 프로세스까지 정리한다 — `tmux kill-session`은 pane 셸만 끊어 재현 세션의 `xcodebuild`가 고아로 남았다. 자손 판별은 경로 매칭이 아니라 ppid — 경로로 잡으면 사람의 Xcode를 죽인다. **파괴적 목록(kill 대상)엔 상한·드라이런·자기 제외가 먼저 들어간다** — 같은 날 트리 계산 버그로 786개 프로세스를 자해한 사고에서. 모든 kill 경로는 watch.log에 한 줄을 남긴다(무로그 kill이 사망 원인 추적에 40분을 먹었다).

## 03. MR 하나의 흐름

| 단계 | 시점 | 무슨 일이 | 누가 |
|---|---|---|---|
| **감지** | 최대 3분 | `needs_review` 등록 + 알림. 본인 MR→`own`, Draft→`draft`로 이탈. | 워처 |
| **리뷰** | 보통 3분 내 시작 | 일회성 세션 스폰(동시 2건) → 결과 JSON 저장 → 세션 종료 → **✅ 리뷰 완료 알림**(sha당 1회). 끝나면 다음 대기 건이 바로 뜬다. | 리뷰 세션 |
| **확인** | 사람이 볼 때 | 근거·재현 절차 확인. 질문하거나 2차 의견을 받을 수 있다. 안 보고 지나가면 **👁 안 읽은 리뷰** 다이제스트가 하루 한 번 알린다. | 사람 · 질문 루프 · 재검토 |
| **등록** | 버튼 누를 때 | Approve/코멘트. 입력칸에 보이는 그대로 나간다. | 사람 → 서버 |

- **재리뷰 트리거 4종** — 새 커밋 · base 이동(스택 MR 부모 머지) · Draft 해제 · 팀 자체 WIP 라벨 해제(GitLab 기본 Draft에 안 잡혀 작업 중 MR이 리뷰된 사고에서).
- **재리뷰는 델타** — `[해결됨]`/`[반증됨]` 표시 + 새 변경분만 추가. 해결된 이슈의 2차 의견 판정도 함께 폐기.
- **승인 뒤 새 커밋을 기다리는 MR**은 큐 보호로 status가 `needs_review`에 남고, 대시보드는 이를 `✅ 승인 · 새 커밋 대기`로 표시한다. 리뷰 중인 MR에 승인·코멘트를 달아도 마찬가지로 보류돼, 세션이 완료 표시 없이 죽어도 재큐가 살아 있다.
- **참고 자료(기준·패턴·프로필)는 리뷰 세션이 매번 새로 읽는다**(stateless) — 고치면 **다음 리뷰부터 자동 반영**. 상주인 질문 루프만 🔄 재기동이 필요하다.

## 04. 리뷰 품질을 만드는 파일들

프로세스끼리는 API 없이 파일로만 소통한다. 그중 단순 연결통로·생존 신호(`state.json` · `chat/*.jsonl` · `.poll-heartbeat`)는 빼고, **리뷰의 정확도·문장·심각도에 실제로 관여하는 파일**만 추리면 이렇다. 리뷰 세션은 **매번 새로 읽으므로 고치면 다음 리뷰부터 바로 반영**된다(상주인 질문 루프만 🔄 필요).

| 파일 | 내용 | 품질에 어떻게 관여하나 |
|---|---|---|
| `session-review.md` `chat-protocol.md` `recheck-protocol.md` `deep-round-protocol.md` `repro-protocol.md` | 리뷰·질문·재검토·심화·재현 세션의 지시서 (세션마다 하나씩) | 각 AI 세션의 **행동 규칙 그 자체** — 리뷰 절차·실측 규칙·판정 기준·금지 사항. 규칙 변경 = 코드가 아니라 이 문서 수정 |
| `~/.claude/CLAUDE.md` UserPromptSubmit 훅 | 이 맥의 Claude Code 전역 설정 (시스템 폴더 밖) | **세션의 기본 규율** — 훅이 매 프롬프트에 추론 규율(실측 우선·[검증됨/가설] 표기·반증 먼저)을 주입하고, 전역 지침이 SwiftUI 체크리스트 필독 등을 강제. ⚠️ 머신 설정이라 **배포에 안 실림** — 팀 배포 전에 프로토콜로 이관 예정 |
| 사람이 관리하는 리뷰 기준 | 리뷰 기준 13관점 · SwiftUI 점검 목록 — 리뷰를 거듭하며 관점을 추가해온 학습형 기준. 무인 루프는 읽기만 하고, 변경은 항상 사람이 낀 자리에서 | 리뷰가 **무엇을 찾을지** 정하는 렌즈 — 이슈 발굴의 출발점. 관점이 여기 없으면 그 유형은 안 잡힌다(73건 동안 죽어 있던 관점 사고) |
| `patterns.md` · `suppressions.json` | 학습된 프로젝트 패턴 · 오탐 판명 억제 목록 | **정확도** — 이 저장소 관례에 맞는 판단 · 이미 오탐으로 판명난 유형 재지적 방지 |
| `recheck-lessons.md` | 2차 의견 판정에서 나온 교정을 자동 누적 (2026-09-18) | **되먹임** — 재검토가 1차 지적을 뒤집을 때마다 그 이유가 쌓이고, 같은 교정이 3회 반복되면 `patterns.md`로 승격된다. 리뷰 세션이 기준과 함께 읽는다 |
| `feedback.jsonl` | 등록/건너뜀/무시 이력 (append-only, 205줄) | **지적 선별** — 자주 채택되는 유형은 강화, 건너뛴 유형은 오탐 후보, Approve만 하고 안 단 유형은 근거 보강 신호. `comment_one` 줄의 초안/전송/변경 여부로 **초안과 실제 코멘트의 차이**를 배운다 |
| `reader-profile.md` | 질문에서 승격된 작성 지침 10개 + 실제 코멘트 실측 | **문장 품질** — 용어 괄호 풀이·결론 먼저·조건부 위험 명시 등, "질문이 안 나오는 리뷰"가 목표 |
| `comment-corpus.jsonl` | 실제로 GitLab에 등록한 코멘트 191건 (매일 자동 증분) | **말투·분량** — 초안이 리뷰어가 실제로 쓰는 문장에 수렴한다(실측 중앙값 50자·질문형 33%). 지침이 아니라 **실물 예시**라 "동료 말투"가 추상적으로 남지 않는다 |
| `repro-routes.md` | 🧪 재현용 앱 화면 도달 경로 쿡북(363줄, 2026-09-10 시딩) | **주장의 검증 속도** — 재현 시간의 35%가 화면 진입·조작이었다. 딥링크·로그인·데이터 준비법이 쌓일수록 재현이 빨라진다. 재현 세션은 공통·함정·대상 화면 절만 **표적 읽기**하고, 64KB를 넘으면 대시보드 칩이 정리를 알린다 |
| `reviews/mr-N.json` | 리뷰 정본 — 이슈·근거·2차 의견·심화 판정 | **MR별 리뷰 기억** — 재리뷰가 이전 지적을 읽어 [해결됨]/[반증됨] 델타를 만들고, 받아둔 2차 의견 판정을 이관·소화한다. 심화가 1차를 뒤집으면 이슈를 고치지 않고 `deep_verdicts`에 판정을 남긴다 |

### 학습이 실제로 도는 예 — 어떤 행동이 무엇을 남기고, 다음 리뷰가 어떻게 달라지나

- **지적을 반증하면** → "두 화면 글자 색이 다르다"는 지적에 "실제 코드는 투명도 72%가 이미 들어 있어 같다"고 반증 → `patterns.md`에 "색·수치 주장은 정의 코드까지 내려가 확인" 항목이 추가됨 → 이후 리뷰는 색 주장 전에 정의부를 열어 확인 (같은 오판 재발 0).
- **리뷰에 질문하면** → "좀 더 예시 들어줄 수 있나?" 류 질문이 2건 쌓임 → `reader-profile.md` 관찰 → 작성 지침으로 승격("추상 메커니즘엔 ①②③ 실제 시나리오를 넣어라") → 이후 코멘트가 예시를 선제 포함해 그 질문 자체가 안 나옴.
- **초안을 고쳐서 올리면** → 초안과 실제 코멘트가 쌍으로 남는다. 실측하니 리뷰어는 초안을 그대로 쓰는 일이 거의 없고 **같은 자리에 자기 관찰을 새로 쓴다**(16쌍 중 12) → 리뷰어는 "편집률"이 아니라 그 **차이**를 읽는다.
- **같은 유형을 계속 건너뛰면** → `feedback.jsonl`에 건너뜀이 누적 → 다음 세션이 그 유형을 오탐 후보로 취급 — 재지적할 땐 근거를 더 두껍게 쓰고, 확신 낮으면 자제.
- **체크리스트에 절을 직접 추가하면** → "모디파이어 순서" 절 신설 → 바로 다음 리뷰부터 그 렌즈가 켜져 렌더 비용 지적 4건이 새로 발화 — 추가 전엔 0건이던 유형.
- **코멘트를 이해 못 해 문구를 지적하면** → "무슨 말인지 모르겠는데" → 해당 프로토콜에 형식 규칙이 박힘(예: 결론은 사람 말 1~2줄, 측정 로그는 접힌 근거로 분리) → 다음 판정부터 그 형식이 강제됨.

## 05. 리뷰 품질 장치

### 규칙 — 추측 금지, 실측만
소스를 직접 열어 결론. 못 하면 `[가설]` 명시. **"실측"은 실행되는 코드만** — 문서·주석·디자인 스펙은 또 하나의 주장일 뿐 (문서가 alpha 0.72를 생략해 오판한 사고에서).

### 필드 — 어떻게 확인했나 + 재현 방법
모든 이슈에 측정 행위·결과값. 동작 버그엔 4요소 재현 절차, 성능 지적엔 "몇 번 찍히면 성립"인 로그 프로브까지. 무인 재현까지 노리면 진입 라벨 사슬·데이터 만드는 법·grep 가능한 판정 문자열이 추가로 붙는다.

### 규칙 — diff는 전량 정독
diff를 파일로 받아 **첫 줄부터 끝까지 `Read`** 한다. 정규식·grep으로 관심 파일만 뽑아 보는 건 리뷰가 아니라 조회다 — 필터에 안 걸린 코드는 시야에 들어온 적조차 없다.

> 동료가 잡은 실버그를 루프가 놓친 건을 부검했더니, 120KB diff를 저장해두고 `Read` 0회에 정규식 4조각만 본 것이 원인이었다(대조 실험 6/6은 전량 정독으로 발견). 부담되면 줄이지 말고 **청크로 나눈다**.

### 자동 검사 — 거짓말 탐지
리뷰 완료 시점에 기계 검사 — 제안 코드의 **미존재 심볼**, 빈 검증 근거. 걸리면 대시보드에 ⚠️ 표시. 세션이 ⚠️를 고치고 완료 표시를 다시 불러도 부수 효과(심화 큐잉 등)는 같은 sha에 no-op — **완료 표시는 멱등**이어야 한다(2026-09-07).

### 규칙 — "몇 건"에는 엔진과 명령을 붙인다
개수 주장은 전용 도구(`xgrep`)로만 — 어떤 엔진·어떤 패턴·몇 건인지가 근거에 남는다. **0건 주장엔 대조군 필수**(같은 명령이 다른 곳에선 잡히는지). 잘린 출력으로 세는 것도 금지.

> 셸마다 `grep`이 다른 것으로 바뀌어 있어(정규식 방언·기본 옵션 차이) 같은 명령이 다른 수를 낸 적이 있다.

### 자동 검사 — 회귀 테스트 35개 파일 · 1,929줄
상태 전이·세션 회수·학습 경로·큐 보호를 격리 환경에서 검증. 테스트는 **전용 tmux 소켓**만 보므로 진행 중인 실세션을 건드릴 수 없고, 실세션이 살아 있으면 스위트가 아예 멈춘다. 격리 목록 자체도 테스트가 감시한다 — 새 경로 전역을 추가하면 격리 테스트가 먼저 깨진다.

**정적 가드**도 테스트다 — status를 직접 대입하는 위치를 함수별 개수로 고정(서버는 0건). 불변식을 함수로 옮겨도 "부르지 않는 코드"는 못 막기 때문에, 같은 필드를 직접 쓰는 곳을 전수 grep한 결과를 테스트로 박아 둔다.

> 회수 테스트가 상한을 0으로 낮춘 채 공유 tmux를 훑어 **진행 중이던 실제 리뷰 3건을 죽인** 사고에서.

### 학습 — 피드백 루프
등록=강화 · 건너뜀=오탐 신호 · Approve만 하고 안 단 것=약한 신호. 질문에서 나온 이해 격차는 작성 지침으로 승격(현재 10개). 프로토콜이 "기록하라"고 해도 새는 경우가 있어, **학습 기록은 모델 준수에 걸지 않고** 워처가 판정을 보고 멱등으로 대신 쓴다.

### 코멘트 작성 규칙
- **증상으로 번역** — "그래서 사용자는 무엇을 못 하나" 한 문장 필수. 메커니즘만 보면 심각도를 잘못 매긴다.
- **제목의 주어를 생략 금지** — "테스트 0건"은 기존 테스트 결함으로 오독됨. 테스트 부재 지적은 🧪 배지 + "테스트가 빠져 있음" 명시.
- **조건부 위험은 조건과 함께** — "지금은 정상, 나중에 X 되면 그때 Y" 구조로.
- **SwiftUI는 동작·렌더 비용 2패스** + 모디파이어 순서. 요약에 "렌더 패스 N건" 한 줄 필수 — "안 봤다"와 "봤는데 없다"를 구분.
- **코멘트는 2줄·200자**, 함수 이름으로 위치 지칭, 라인번호 없이, 동료 말투.

## 06. 두 번째 패스 — 심화 · 2차 의견 · 직접 확인

### 🔬 심화 라운드 — 수동 + 재개 (자동 발화 OFF, 2026-09-18)

**1차가 못 보는 두 축을 더 판다.** 일회성 세션이 서브에이전트 둘을 **서로 다른 모델로** 병렬 실행한다(같은 모델 둘은 맹점을 공유한다).
① **수정 파일 전문 + 1-hop** — 1차는 diff까지만 본다. 기존 파일을 고친 변경이 그 파일의 나머지·호출부와 어떻게 맞물리는지.
② **크로스커팅 시나리오** — MR 설명에서 사용자 여정을 도출해 모듈 경계를 관통. 발견은 기존 리뷰에 이슈로 합쳐진다.

두 라운드가 같은 지점에서 **엇갈리면 그 자체가 최고 순도의 검증 신호** — 다수결·선착순이 아니라 원문(head raw)으로 판정한다.

**자동 발화를 끈 이유(2026-09-18, 30일 실측):** 심화가 전체 지출의 **39%**인데 심화가 낸 지적의 등록은 **0/82**, 재열람해도 채택 0. 게다가 자동 발화 18건 중 10건은 하루 상한·동시 1건 제한에 밀려 **머지 뒤에야** 돌았고, 그중 다수는 상태 덮어쓰기 버그로 히스토리 등록까지 잠겨 있었다(09-23 15건 `merged` 복구). 다시 켜려면 `MR_DEEP_AUTO=1` — 그 전에 "머지 뒤 스폰"을 막을지 먼저 정한다. 버튼(수동)과 재개는 그대로.

**잘려도 잃지 않는다(2026-09-04)** — 서브에이전트 결과가 **도착하는 즉시 파일로 남고**, 상한에 걸려 잘리면 다음 순번이 비싼 재실행 없이 **병합만** 이어받는다. 예산도 실측(완주는 전부 33분 이내, 절단은 35분에 몰림)에 맞춰 45분으로 올렸다. 라운드 0인 채 죽으면 1회 재시작, 커밋이 바뀌면 라운드가 완비돼도 폐기한다 — 새 커밋은 새 심화 사유다.

> 자동 발화를 결과가 아니라 크기(±50줄)로 걸었던 이유 — 4주 81건 백테스트에서 "1차가 조용한 MR"에 진짜 버그가 있던 사례가 나왔다. 지적 건수로 게이트를 세우면 그런 MR을 정확히 놓친다. 논리는 맞았지만 30일 운영에서 **채택이 0**이라, 지금은 사람이 필요할 때만 켠다.

### 🔁 2차 의견 재검토 — 다른 세션에게 반증 시키기
이슈별 버튼 → **일회성 최신 모델 세션**이 그 이슈만 들고 "틀리게 만들 증거"를 먼저 찾는다. 끝나면 판정만 남기고 스스로 정리. **리뷰 본문은 안 건드림** — 교정안이 오면 ✅ 반영 버튼으로 사람이 적용(↩️ 되돌리기 가능).

판정에서 나온 교정은 `recheck-lessons.md`로 되먹임돼 다음 리뷰가 읽는다. 크레딧 게이트가 뜨면 감시자가 다른 모델로 자동 교체, 35분 넘으면 강제 정리.

### 🧪 런타임 재현 — 수동 (실행 9회) — 말로 다투지 말고 돌려본다
전용 워크트리(전용 DerivedData)에 그 커밋을 체크아웃해 빌드하고, 시뮬레이터를 조작해 계측한다. 판정은 **재현됨 · 반증됨 · 판정 불가** 셋. 판정에는 **양성 대조군**(장치가 살아 있다는 증거)과 **기전 대조군**(겨냥한 상황이 실제로 일어났나)이 함께 붙는다. 진행 중이면 🧪 버튼이 중지 토글로 바뀐다.

**하네스 하드닝(2026-09-07~21)** — 외부 빌드 도구는 필요한 순간에 명시적으로 찾고 없으면 원인과 함께 멈춘다(모델이 우회할 수 있는 실패는 침묵한다). 시뮬레이터는 빌드 도중 꺼지므로 설치·조작 직전마다 `simctl bootstatus` 멱등 가드. 프로젝트 생성 캐시 스탬프는 **입력 전체집합**(파일 구성 + Swift 소스 외 내용)에서 시작 — 예전 스탬프가 새 파일을 못 봐서 빌드가 깨진 교정.

> 시간 분해(5세션 175분): 화면 진입·조작 35% · 빌드 22% · 자료 준비 16%. 그래서 쿡북(`repro-routes.md`)을 시딩했다 — 딥링크가 가장 큰 지렛대. 첫 클린 빌드는 실측 462초, 이후 증분. 판정 불가로 끝난 건은 전부 **데이터가 없어 그 상황을 못 만든 것**이라, 수치가 지적에 불리하게 나왔어도 **반증으로 세지 않았다**. 조건 미성립과 반증을 섞으면 학습이 오염된다.

### 🔧 디버그 준비 시키기 — 내 눈으로 볼 준비 시키기
프롬프트 복사 → Claude Code에 붙여넣으면 브랜치 체크아웃 + 판정 장치 삽입까지. 실행·판정은 사람 몫.

철칙: **지적이 맞든 틀리든 같은 결과가 나오는 장치는 장치가 아니다.**

### 판정 배지
`지적 맞음 → 배지 없음` · `🔁 지적 손질 필요` · `🔁 지적 틀림` · `🔁 판정 불가` · `🔁 2차 의견 반영`

- 제목줄엔 **행동이 필요한 판정만** 뜬다 — "맞음"은 할 일이 없으니 침묵.
- 판정 본문은 **사람 말 결론 1~2줄** + 접힌 측정 근거로 분리 — 라인번호 로그가 독자 자리에 오지 않게.
- 해결·반증 판정은 제목 접두어가 아니라 **구조 필드**(`refuted_by`·`recheck.verdict`·`retracted`)로 남기고, 표시는 읽는 지점에서 파생한다. 접두어만 보던 시절 재검토 반증 5건이 활성으로 떠 있었다.

| 지난 리뷰 보기 | 🗂 히스토리 | 머지·클로즈 MR 30일 보존. **머지된 MR에도 코멘트 등록 가능**(2026-08-25 — 심화가 머지 직후 끝나는 경우가 있어서). closed는 불가. 머지되면 **심화가 돌고 있어도 목록에서 히스토리로 즉시 넘어간다**(2026-09-04) — 파일 이동만 세션이 끝날 때까지 미룬다 |
| 이슈가 많아 흩어진다 | ⭐ 추적 · 필터 칩 | 별표한 이슈를 상단 고정, 심각도·⭐로 걸러 보기. **✓등록됨은 묶음 칩과 무관하게 가산**이라 warning·info를 끄면 등록한 것만 남는다. 필터로 전부 숨겨지면 화면이 이유와 **초기화 버튼**을 띄운다(2026-09-06) |
| 이 이슈만 물어보고 싶다 | 💬 이슈별 질문 | 질문창이 그 이슈에 묶이고, 답도 이슈 번호를 달고 온다 |
| 리뷰 규칙 변경 | 지시서 수정 | `session-review.md` 본문에 직접 (링크만 걸면 안 읽힘) — 다음 리뷰 세션부터 자동 반영 |
| 자동 심화를 다시 켜고 싶다 | `MR_DEEP_AUTO=1` | 설정 파일 한 줄. 켜기 전에 "머지 뒤 스폰"을 어떻게 막을지부터 정한다 |

- **엔진 배지** 🟢 정상 / 🟡 지연 / 🔴 워처 정지(3분 poll 기준) + **리뷰 중 N · 대기 M** 카운트 — 상주 루프가 없어져 "루프 생존" 대신 워처와 진행 세션을 그대로 보여준다.
- **상태 표시** — 승인 뒤 새 커밋을 기다리는 MR은 `✅ 승인 · 새 커밋 대기`. 리뷰 중 보류는 `🔄 리뷰 중` 그대로.
- **화면은 알아서 최신** — 재검토 완료·재리뷰 결과가 클릭 없이 뜨고, 대시보드 코드가 바뀌면 탭이 스스로 새로고침. 단 **코멘트 작성 중엔 보류**.
- **긴 글은 전부 기본 접힘** + "펼치기" 배지. 해결·반증된 이슈는 기본 숨김.
- **서버 재기동은 한 체인으로만** — 실세션 확인 → 문법 검사 → 드라이런 → `launchctl kickstart`. 검증이 실패하면 재기동 줄이 실행될 수 없다(순서를 어겨 3분 다운된 사고 2건에서).

## 08. 비용 · 권한

- **API 키·헤드리스(`claude -p`) 안 씀** — 대화형 세션 + 구독 로그인이라 추가 요금 0, 구독 한도만 차감. 배너의 "Claude API"는 인증 방식 표기일 뿐.
- **"비용 0"의 조건은 둘** — ①실행 방식(대화형) ②모델이 구독에 포함될 것. 구독 밖 모델은 **요금이 아니라 정지**로 나타난다(크레딧 다이얼로그에서 멈춤).
- **사용량의 39%를 먹던 자동 심화를 끄면서**(2026-09-18) 남은 지출은 1차 리뷰·2차 의견·질문 루프·수동 심화·재현뿐이다.
- **긴 수명(1년)의 구독 토큰**(`claude setup-token`)을 파일로 두고 셸 안에서 주입 — 무인 재기동에도 로그인이 안 풀리고, 토큰 값이 `ps`에 안 보임. 일회성 세션은 전부 이 토큰으로 인증하고, 그 세션에 뜨는 "Claude.ai login was rejected" 경고는 무해하다(8회 대조).
- **권한은 allowlist** — 파일·셸·화이트리스트 도메인(GitLab·Apple 문서·GitHub raw)만. 그 밖(메신저·브라우저·임의 도메인)은 승인 대기로 멈춤. 리뷰 대상이 남의 코드라 주입 지시문이 있어도 손 닿는 범위가 좁다.
- **무인 세션의 실패는 침묵이다** — 권한 창에서 59분, 크레딧 창에서 2시간 멈춘 사고 둘 다 "로그는 정상". 대응은 allowlist 정비 + 원인 불문 타임아웃 — 그리고 상주 리뷰 루프 자체를 폐지(2026-08-26)해, 블록돼도 피해가 그 MR 한 건·최대 90분으로 갇힌다.

## 09. 알아둘 한계

- **리뷰 시작까지 보통 3분, 최대 ~6분** (감지 3분 + 드레인 3분) — 급하면 ▶. 동시 2건 초과분은 앞 건이 끝나는 즉시 이어 뜬다.
- **대형 MR(50파일/4천 줄↑)은 분할 리뷰** — 890파일을 한 패스로 훑다 이슈 5개만 낸 실패에서.
- **맥이 잠들면 워치독도 잠든다** — 총량 상한은 벽시계 비교라 슬립 구간이 흐르고, 정체 감지만 루프 시간이다. 슬립을 넘긴 심화는 현 구조에선 손실이고 스테이징만이 방어다(뚜껑 닫힘 23:55 → 첫 다크웨이크 00:33에 kill된 사례). `caffeinate`는 idle sleep만 막는다.
- **런타임 검증은 조건이 맞아야 한다** — 🧪 재현이 정적 분석의 경계를 밀어냈지만, 판정 불가로 끝난 건은 전부 **테스트 환경 데이터로 그 상황을 만들 수 없어서**였다. 억지 결론 대신 미결로 남기는 것이 규칙이다. 재현 기기는 실행마다 다르고(iPhone 16 / 16 Pro), 시뮬레이터는 빌드 도중 꺼지므로 전제조건은 쓰기 직전마다 확인한다.
- **틀린 지적은 여전히 나온다** — 장치는 확률을 낮출 뿐. 2차 의견도 의견이다. 최후 방어선은 사람.
- **본인 MR 판별은 휴리스틱** — 명의 정확 일치 + 자동화 계정 명의 사람 커밋 과반. "지금까지 본 입력"을 규칙으로 삼으면 첫 예외가 통과한다 — 석 달간 본인 MR이 전부 자동화 계정 명의였다는 관측이 규칙이 돼 첫 직접 명의 MR이 리뷰 세션까지 떴다(09-23). 수동 지정 명령 있음.
- **맥이 켜져 있어야 한다** — 로컬 상주. 서버는 127.0.0.1 전용. 리뷰 스폰이 서버를 거치므로 서버가 죽으면 리뷰도 대기(KeepAlive + 3분 재시도로 복구). launchd의 `/usr/bin/python3`는 `xcode-select`를 따르므로, Xcode를 바꾸면 데몬 인터프리터도 바뀌고 떠 있는 서버는 재기동해야 옮겨간다(09-23).
- **아직 이 맥 전용** — 경로·계정·개인 Claude 설정(전역 지침·훅)에 기대는 부분이 남아 있다. **설치 스크립트(install.sh)로 팀 배포 예정** — 개인화 제거(Phase 0) 후 동료 맥에 현행 구조를 그대로 복제하는 방식.
